데이터·AI 거버넌스 정책

본 정책은 경찰청 AI 통합플랫폼에서 다루는 모든 데이터와 모델의 수명주기 — 수집·라벨링·학습·추론·로깅·폐기 — 에 적용되는 최소 기준선입니다. 책임 있는 AI 운영을 위한 6대 원칙과, 데이터 자산을 의미론적으로 통제하기 위한 4대 거버넌스 기둥으로 구성되어 있으며, 사법기관 사용 환경의 특수성을 반영하여 한층 강화되었습니다.

Section 00

정책 개요

AI는 수사 효율을 비약적으로 높일 수 있지만, 동시에 한 사람의 자유·명예·재산에 직접 영향을 미치는 결정의 근거가 됩니다. 본 정책은 그 결정 하나하나가 설명 가능하고, 추적 가능하며, 책임이 명확한 상태에서 이뤄지도록 설계되었습니다.

정책의 골격은 두 가지 산업 표준을 참고하여 경찰 환경에 맞게 재구성되었습니다 — 책임 있는 AI 운영 원칙은 마이크로소프트의 Responsible AI Standard를 출발점으로, 데이터를 다루는 통제 구조는 팔란티어(Foundry)의 데이터 거버넌스 모델을 참조했습니다. 두 체계의 공통점은 분명합니다: 의미 있는 인간의 통제(meaningful human control)가 자동화의 모든 단계에 박혀 있어야 한다는 것입니다.

적용 대상 본 정책은 ISP 플랫폼에서 운영되는 모든 모델·에이전트·파이프라인과, 이를 사용하는 모든 인적·시스템 행위자에게 예외 없이 적용됩니다. 위탁 개발사·외부 자문 인력 또한 동일한 의무를 집니다.

Section 01

책임 있는 AI 6원칙

모든 모델은 기획 단계부터 폐기까지 다음 6가지 원칙을 동시에 충족해야 합니다. 어느 하나라도 임계치를 만족하지 못하는 모델은 배포 게이트를 통과할 수 없습니다.

PRINCIPLE 01
공정성 (Fairness)

모델은 연령·성별·지역·국적 등 보호 속성에 따라 체계적으로 다른 결과를 내놓아서는 안 됩니다. 평가 단계에서 집단 간 정확도 격차가 ±3%p를 초과하면 배포가 차단됩니다.

PRINCIPLE 02
신뢰성·안전 (Reliability & Safety)

모델은 예상된 입력 분포 내에서 일관된 성능을 내야 하며, 분포 밖 입력에 대해서는 자신 있게 "모름"을 반환해야 합니다. 운영 중 드리프트가 감지되면 자동 롤백 또는 검토 보류로 전환됩니다.

PRINCIPLE 03
프라이버시·보안 (Privacy & Security)

모든 개인식별정보는 최소 수집·최단 보존을 원칙으로 합니다. 학습 전 비식별화·차등 프라이버시 기법을 적용하며, 모델은 학습 데이터를 그대로 토해내지 않도록(memorization defense) 정기 점검됩니다.

PRINCIPLE 04
포용성 (Inclusiveness)

접근성·다국어·다문화 사용자가 동일한 품질의 서비스를 받을 수 있도록 설계합니다. 한국어 외 다문화 가정·외국인 신청인 응대 모델은 별도 평가 셋으로 검증합니다.

PRINCIPLE 05
투명성 (Transparency)

모든 운영 모델은 모델 카드를 보유합니다 — 학습 데이터의 출처·범위, 알려진 한계, 평가 결과, 적합한 사용 사례, 적합하지 않은 사용 사례까지 공개됩니다. 추론 결과에는 항상 근거가 함께 표시됩니다.

PRINCIPLE 06
책임성 (Accountability)

모든 모델·에이전트에는 명시된 책임자(owner)가 있고, 모든 자동 결정에는 인간 결재자가 지정됩니다. 최종 처분에 영향을 미치는 결정은 AI 단독으로 내릴 수 없으며 반드시 사람의 검토를 거쳐야 합니다.

인간 결재 원칙(human-in-the-loop) AI가 제시한 결과는 어디까지나 참고 자료이며, 신병 조치·압수수색 영장 청구·기소 의견 제출 등 강제력을 동반하는 모든 처분은 담당 수사관과 결재선의 판단으로만 이뤄집니다. AI 출력만으로 처분을 결정한 사실이 드러날 경우 절차 위반으로 간주됩니다.

Section 02

데이터 거버넌스 4기둥

데이터는 단순한 파일이 아니라, 의미·출처·목적·권한이 함께 묶인 하나의 거버넌스 객체로 다뤄집니다. 모든 객체는 다음 네 가지 통제 축 아래에서만 시스템 내부를 이동할 수 있습니다.

PILLAR I
온톨로지 기반 의미 계층

원천 시스템(KICS·CMS·SCAS·CCTV)에서 들어온 모든 데이터는 플랫폼의 통합 온톨로지에 따라 객체(피의자·차량·사건·증거)와 관계(연루·소유·발생)로 매핑됩니다. 모델·에이전트·쿼리는 모두 원시 테이블이 아니라 온톨로지 객체 단위로 데이터를 요청합니다.

이 계층 덕분에 "이 사람의 모든 관련 사건"과 같은 의미적 요청에 대해 정책 엔진이 권한·목적을 일관되게 판단할 수 있습니다.

PILLAR II
출처·리니지 추적

모든 데이터 객체는 어디서 왔는지(원천 시스템·수집 시점·수집 근거 법령)와, 어떤 변환을 거쳐 현재 상태에 이르렀는지(전처리·비식별화·집계 단계)의 전체 계보를 보유합니다. 모델이 학습에 사용한 데이터와 추론 시 참조한 데이터 모두 역추적이 가능합니다.

UPSTREAM
원천 시스템과 수집 시각, 수집 근거 조항을 자동 기록
TRANSFORM
모든 전처리 스크립트의 버전·실행자·실행 시각
DOWNSTREAM
해당 데이터를 사용한 모델·에이전트·리포트 목록
PILLAR III
목적 제한 (Purpose-Based)

각 데이터 객체에는 수집 시 명시된 허용 목적(purpose) 라벨이 부여됩니다. 동일한 사용자라 하더라도 현재 수행 중인 업무 목적이 라벨과 일치하지 않으면 접근이 거부됩니다 — 권한이 아니라 지금 무엇을 하려는가가 통제의 기준이 됩니다.

예: 「차량 절도 수사」 목적으로 등록된 CCTV는 동일 사용자라도 「민원 응대」 세션에서는 호출할 수 없습니다.

PILLAR IV
세분화된 접근 통제

접근 권한은 행(row)·열(column)·셀(cell) 단위까지 분해되며, 역할(RBAC)·속성(ABAC)·목적(PBAC)의 세 축을 동시에 평가하여 결정됩니다. 동일한 테이블이라도 사용자에 따라 보이는 행과 마스킹되는 열이 달라집니다.

모든 접근 결정은 정책 엔진이 단일 지점에서 평가하며, 결정 사유와 함께 영구 로그로 남습니다.

Section 03

데이터 분류 등급

모든 데이터 객체는 등록 시 다음 세 가지 등급 중 하나가 부여됩니다. 등급은 자동 분류기 + 데이터 책임자 확인의 이중 단계로 결정되며, 등급 하향(declassification)은 정보보안담당관 승인 사안입니다.

등급 정의 예시 기본 통제
CLASS A 고도 민감
유출 시 수사 중단·인적 위해 우려		 진행 중 수사 자료, 제보자 식별 정보, 미공개 영장 내용, 통신·금융 영장 사본 암호화 저장 · APPROVER 승인 후 열람 · 화면 워터마크 · 다운로드 금지

Section 04

접근 통제 모델

모든 접근 요청은 다음 세 가지 차원의 교집합으로 평가됩니다 — 사용자의 역할, 사용자·세션의 속성, 그리고 현재 선언된 목적. 셋 중 하나라도 만족하지 못하면 요청은 거부됩니다.

Section 05

데이터 수명주기

모든 데이터 객체는 다음 다섯 단계를 따라 흐르며, 각 단계 전환 시 정책 엔진이 다시 평가합니다. 단계 간 이동은 자동 로깅되며 사용자가 수동으로 건너뛸 수 없습니다.

STAGE 01
수집

원천 시스템에서 수집 근거 법령과 함께 적재. 출처 메타가 없는 데이터는 거부됩니다.

STAGE 02
분류·라벨링

자동 분류기 + 데이터 책임자 확인으로 등급·목적·보존 기간 라벨 부여.

STAGE 03
사용

학습·추론·조회의 모든 사용은 목적 일치 검사를 통과한 경우에만 허용.

STAGE 04
보존

등급별로 정해진 보존 기간 동안 암호화 저장. 기간 만료 30일 전 자동 알림.

STAGE 05
폐기

암호 키 파기 → 물리적 무영구화 순으로 이중 폐기. 폐기 증빙은 5년 보관.

Section 06

AI 영향평가 (AIA)

신규 모델 또는 기존 모델의 중대한 변경(아키텍처 교체·학습 데이터 확장·새 추론 시나리오 추가)에 앞서 AI 영향평가서를 작성·승인받아야 합니다.

영향평가는 다음 네 가지 항목을 다룹니다:

  • 의도된 사용 (Intended Use) — 모델이 어떤 의사 결정에 어떻게 기여하는가, 사용 범위와 사용 금지 범위를 모두 명시.
  • 이해관계자 영향 (Stakeholder Impact) — 잘못된 출력이 시민·피의자·수사관 각각에게 어떤 결과를 초래할 수 있는지, 회복 가능성과 함께 평가.
  • 대안 검토 (Alternatives Considered) — AI가 아닌 방법(규칙 기반·인간 분석)을 검토했는지, AI 채택의 필요성과 비례성 논증.
  • 완화 조치 (Mitigations) — 식별된 위험에 대한 기술적·절차적 완화 조치, 잔여 위험의 수용 사유와 책임자.

AIA는 정보화기획단·정보보안담당관·외부 자문위원(법학·인권 분야)으로 구성된 AI 운영위원회에서 심의하며, 위원회는 모델별로 다음 세 가지 처분 중 하나를 의결합니다 — 승인 · 조건부 승인(추가 안전장치 부착) · 반려.

고위험 모델 사람의 신병이나 권리에 직접 영향을 미치는 결정에 사용되는 모델(예: 누범 예측·얼굴 식별·재범 위험도 평가)은 자동으로 고위험으로 분류되며, 외부 인권 전문가의 별도 자문과 6개월 단위 재평가가 의무화됩니다.

Section 07

감사와 추적

시스템 내 모든 행위는 변조 불가능한 감사 로그로 기록됩니다. 로그는 다음 속성을 모두 포함합니다 — 행위자 · 행위 시각 · 행위 유형 · 대상 객체 · 선언된 목적 · 정책 엔진 판단 결과 · 결과 데이터 해시.

  • 변조 방지 — 로그는 append-only 저장소에 기록되며, 매일 자정 머클 트리 해시가 별도 시스템에 백업됩니다. 사후 임의 수정 시 즉시 탐지됩니다.
  • 실시간 이상 탐지 — 정보보안담당관실 SIEM이 24/7로 비정상 패턴(대량 다운로드·심야 접근·권한 외 데이터 조회 시도·반복 거부)을 감시하며, 위협 점수가 임계치를 넘으면 자동으로 세션을 종료합니다.
  • 본인 활동 열람권 — 사용자는 본인의 활동 이력 전체를 언제든 열람할 수 있습니다. 타인 활동 열람은 APPROVER 이상 권한이 필요하며, 열람 행위 자체가 다시 로그로 남습니다.
  • 로그 보존 — 모든 감사 로그는 최소 5년 보관됩니다. 수사·소송 관련 로그는 사건 종결 후 5년이 추가로 적용됩니다.

Section 08

사고 대응 절차

데이터 유출·정책 위반·모델 오작동이 감지된 경우 다음 4단계로 대응합니다. 각 단계의 최대 소요 시간은 SLA로 정의되어 있으며, 초과 시 자동 에스컬레이션됩니다.

PHASE 01
탐지·격리

영향 받은 사용자·서비스·데이터 객체를 즉시 격리. 추가 노출 차단.

SLA · 15분
PHASE 02
영향 평가

리니지를 역추적하여 노출 범위·민감도·외부 유출 가능성 산정.

SLA · 4시간
PHASE 03
신고·통보

개인정보위·정보보호위원회 신고 및 영향 받은 정보주체 통지(필요 시).

SLA · 72시간
PHASE 04
복구·재발 방지

근본 원인 분석(RCA)과 정책·시스템 개선안 수립. AI 운영위원회 보고.

SLA · 30일

Section 09

금지 사항 · 위반 시 조치

다음은 본 정책에서 엄격히 금지되는 행위입니다. 위반이 확인될 경우 「국가공무원법」 및 내부 감찰 규정에 따라 책임을 묻습니다.

  • 목적 외 사용 — 선언된 업무 목적과 무관한 인물·차량·통신 정보 조회. 시스템이 차단하지 못한 사례라도 사후 감사에서 동일하게 처분됩니다.
  • 마스킹 우회 시도 — 자동 마스킹된 개인정보를 복원하려는 모든 시도(프롬프트 인젝션·역공학적 질의 포함).
  • 모델 결과의 단독 의사 결정 — 인간 결재 절차를 생략하고 AI 출력만으로 처분을 결정하거나 그 사실을 은폐하는 행위.
  • 학습 데이터 무단 도입 — 비식별화·법적 근거 확인을 거치지 않은 외부 데이터를 학습에 투입하는 행위.
  • 로그 회피 — 감사 로그를 우회하기 위한 임의 API 호출·계정 공유·세션 위조.
  • 모델·데이터 외부 반출 — 승인되지 않은 채널을 통한 모델 가중치·학습 데이터·추론 결과의 외부 전송.
제재 단계 1차 위반은 경고와 재교육, 2차 위반은 권한 정지(최소 30일)와 감찰 회부, 3차 또는 중대 위반은 즉시 권한 회수와 징계 절차로 진행됩니다. 형사 처벌 사유에 해당하는 경우 별도로 사법 처리됩니다.
